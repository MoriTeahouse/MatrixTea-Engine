# 效能量測

## 重現方式

```sh
pwsh -File scripts/Benchmark.ps1 -IncludePackaging
```

.NET 8 SDK 及完整 Git 歷史為必要條件。封裝基準以 9d56e36 的原始 AtrArchive 編譯獨立 baseline assembly；場景基準保留該版調度熱路徑。節奏比較同一 session 的線性相容模式與欄位索引模式，建構成本不包含於輸入計時。

## 本機樣本（2026-10-01）

Windows x64，.NET 8.0.24，Release，完成暖機；每個案例開始前執行 GC。時間使用 Stopwatch，管理配置使用 GC.GetAllocatedBytesForCurrentThread。測試資料由固定 seed 產生。

| 案例 | 原路徑時間 | 優化時間 | 原管理配置 | 優化管理配置 |
|---|---:|---:|---:|---:|
| 250,000 次 scene update／render 配對 | 20.86 ms | 8.72 ms | 52,000,000 B | 0 B |
| 100,000 音符、500 次輸入 | 76.57 ms | 1.14 ms | 40,000 B | 40,000 B |
| ATR 打包 16 MiB 混合資料 | 302.60 ms | 253.82 ms | 109,928,920 B | 2,259,880 B |

場景調度約 2.4 倍、索引輸入約 67 倍；封裝管理配置約減少 98%。兩種節奏路徑檢查命中數與分數一致；兩種封裝結果均解回原始資料。

## 解讀限制

這是單機微型基準，並未固定 CPU 頻率、執行緒 affinity 或排除其他系統工作；時間是樣本，不是 SLA。索引建構與保留資料需要額外成本，可變 Notes 接入不會得到索引加速。候選窗內極高密度音符仍需掃描候選。

管理配置不是工作集、原生壓縮器記憶體、GPU 記憶體或峰值 RAM。ATR 保留暫存 payload 的磁碟使用；池化不能消除原生壓縮工作。結果不能推定完整遊戲 FPS、音訊延遲或不同裝置上的改善比例。

原始機器可讀報告輸出至 artifacts/benchmark-results.json（不納入版本控制）。標準回歸會另外確認暖機後場景調度及空 miss 輪詢不配置管理物件。性能變更需與行為回歸共同驗證。
